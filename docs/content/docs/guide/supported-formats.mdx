`transpic-cli` relies on the [`image`](https://crates.io/crates/image) crate for decoding and encoding. The input format is auto-detected from the file's contents, so the file extension doesn't need to match the actual format.

## Output formats (`--format`)

The following values are accepted for `--format`, along with their aliases:

| Format | Value(s) for `--format` |
| --- | --- |
| AVIF | `avif` |
| Bitmap | `bmp` |
| OpenEXR | `exr` |
| Farbfeld | `ff`, `farbfeld` |
| GIF | `gif` |
| Radiance HDR | `hdr` |
| Icon | `ico` | |
| JPEG | `jpeg`, `jpg` |
| PNG | `png` |
| PNM | `pnm` |
| QOI | `qoi` |
| TGA | `tga` |
| TIFF | `tiff`, `tif` |
| WebP | `webp` |

<Callout type="warn">
  Passing any other value to `--format` returns an `Unsupported output format` error. See [Troubleshooting](/docs/troubleshooting) for details.
</Callout>

## Input formats

Input format detection is automatic — `transpic-cli` reads the file's magic bytes rather than relying on its extension. In practice, this covers the same set of formats listed above (PNG, JPEG, GIF, BMP, ICO, TIFF, WebP, AVIF, PNM, QOI, TGA, Farbfeld, and OpenEXR/HDR), as supported by the underlying `image` crate.

If `--format` is omitted, the output is encoded back to the **same format the input was detected as**.

## Choosing a format

- Use **PNG** for lossless output and when transparency matters.
- Use **JPEG** or **WebP** for smaller file sizes with photographic content.
- Use **WebP** or **AVIF** for the best size-to-quality ratio if your target platform supports them.
- Avoid converting images with transparency to **JPEG**, since the alpha channel will be discarded.
